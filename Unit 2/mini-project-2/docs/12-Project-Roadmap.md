# 12. Project Timeline and Release Roadmap

This is a sample roadmap. Replace the relative timing with actual dates agreed by the team.

| Stage | Main activities | Target deliverable |
|---|---|---|
| Discovery and planning | Review business problem, stakeholders, requirements, personas, and MVP | Product Vision and initial Product Backlog |
| Sprint 1 | Repository setup, authentication planning/development, initial tests | Project foundation and authentication increment/design |
| Sprint 2 | Student registration, search, update, and deletion rules | Student management increment/design |
| Sprint 3 | Course management and attendance | Course and attendance increment/design |
| Later iteration | Marks, grades, reports, and notifications | Extended academic features |
| Release preparation | Acceptance checks, security review, documentation, stakeholder feedback | Release candidate and final report |

## Release strategy
Deliver core capabilities first. Authentication and student records form the foundation; course and attendance features follow; marks, reports, and notifications can be added in later iterations.

## Risks and responses
- **Unclear requirements:** Confirm requirements with stakeholders before development.
- **Scope growth:** Protect the MVP and prioritize new requests in the backlog.
- **Incorrect academic data:** Validate input and test record operations.
- **Unauthorized access:** Define roles and check permissions for protected features.
- **Limited time:** Select work based on team capacity and review progress each Sprint.
