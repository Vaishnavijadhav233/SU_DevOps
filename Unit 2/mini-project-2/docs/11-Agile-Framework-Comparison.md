# 11. Comparison of Agile Frameworks

| Framework | Main focus | Advantages | Considerations for this project |
|---|---|---|---|
| Scrum | Iterative work in time-boxed Sprints with defined accountabilities and events | Clear goals, regular review, visible backlog | Suitable for a student team that needs planned checkpoints |
| Kanban | Visualizing workflow and limiting work in progress | Flexible flow and easy status tracking | Useful for continuous support and task tracking |
| Extreme Programming (XP) | Engineering practices such as frequent testing, refactoring, and pair programming | Helps improve code quality and feedback | Useful if the team is actively building software and can adopt its practices |
| Lean Development | Maximizing value and reducing waste | Encourages simple processes and continuous improvement | Helpful for keeping the MVP focused |
| Large-Scale Scrum (LeSS) | Applying Scrum across multiple teams working on one product | Supports coordination across teams | Likely more structure than a small student project needs |
| Scaled Agile Framework (SAFe) | Coordinating Agile delivery across a large enterprise | Provides portfolio and program-level coordination | Usually excessive for a small academic project |
| Scrum@Scale | Scaling Scrum through connected Scrum structures | Supports coordination across multiple Scrum teams | More suitable when several teams must coordinate |

## Recommendation
Scrum is a reasonable primary framework for this mini-project because the assignment itself asks for Scrum roles, a prioritized Product Backlog, Sprints, a Scrum Board, and Scrum ceremonies. Kanban-style visualization can support the board, while testing and code review practices from XP can be used if software implementation is undertaken.
